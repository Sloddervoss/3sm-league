# SYSTEM_OVERVIEW

## Wat is dit systeem?

3 Stripe Motorsport is een publieke iRacing league/community website met:

- publieke pagina's voor kalender, uitslagen, standings, coureurs, teams, seizoenen, nieuws en meedoen;
- login/profiel/registratieflows via Supabase Auth;
- admin-, steward- en editorfunctionaliteit;
- Supabase database, RLS, RPC's, storage en edge functions;
- Discord-bot voor raceberichten, registraties, Discord-koppeling, teamrollen, announcements, stewardmeldingen en livestreammeldingen;
- crawler-facing route HTML en sitemapgeneratie voor SEO;
- browser extension voor iRacing track intelligence uploads.

## Runtime architecture

```text
Browser
  -> static Vite app from /var/www/3sm via nginx
  -> Supabase REST/Auth/Storage/Functions via VITE_SUPABASE_URL

Discord user
  -> Discord bot (bot/index.js)
  -> Supabase with SUPABASE_SERVICE_KEY
  -> Discord guild channels/roles/categories

Build/deploy
  -> npm run build
     -> vite build
     -> scripts/generate-route-html.mjs
     -> scripts/zip-extension.mjs
  -> deploy.sh copies dist/* to /var/www/3sm
```

## Data flows

### Race/calendar/results

- Admin creates/edits seasons/races/results via pages under `src/pages/admin/`.
- Public pages read `races`, `race_results`, `leagues`, `profiles`, `teams`, `team_memberships`.
- `/results` and `/results/:raceId` are UI routes in `src/pages/ResultsPage.tsx` and `src/pages/RaceDetailPage.tsx`.
- Build-time route HTML for result detail pages comes from `scripts/generate-route-html.mjs` reading completed races and race results from Supabase.

### Auth/profile/roles

- Supabase Auth session is loaded in `src/contexts/AuthContext.tsx`.
- Roles are read from `user_roles` and mapped to booleans:
  - `admin` -> `isAdmin`
  - `super_admin` -> `isSuperAdmin`
  - `moderator` -> `isSteward`
  - `editor` -> `isEditor`
- New Supabase users get a `profiles` row through `handle_new_user()` trigger from initial migration.

### Discord integration

- Website `/koppel` route (`src/pages/KoppelPage.tsx`) claims Discord link tokens via RPC `discord_claim_token`.
- Bot `/koppel` creates rows in `discord_link_tokens` and returns a site link.
- Bot processes `discord_sync_queue` and syncs Discord nickname/roles/team channels.
- Bot command registration and cron scheduling are in `bot/index.js`.

### News/editorial

- Public news pages read published `news_posts`.
- `src/pages/NewsEditorPage.tsx` requires admin/super_admin/editor.
- News images use Supabase Storage bucket `news-images`.
- SEO route generator creates `/news/<category>/<slug>/index.html` from published posts.

### Track intelligence

- Admin UI: `src/pages/TrackIntelligenceTestPage.tsx`.
- Helpers: `src/lib/trackIntelligence.ts`.
- Edge functions:
  - `supabase/functions/track-intelligence-sync/index.ts`
  - `supabase/functions/track-intelligence-upload/index.ts`
- Extension source: `tools/iracing-content-extension/`.
- Tables are created by `supabase/migrations/20260614130000_track_intelligence_test.sql` and extended by `20260614150500_allow_extension_scan_source.sql`.

## Build artifacts

- `dist/` is generated and should not be treated as source of truth for normal code changes.
- `public/iracing-content-extension.zip` is generated by `scripts/zip-extension.mjs` during `npm run build`; it is tracked in the repo.
- `dist/.route-html-manifest.json` is generated by `scripts/generate-route-html.mjs`.

## Known uncertainties

- `src/integrations/supabase/types.ts` is not fully aligned with latest migrations: track intelligence tables are missing from generated types.
- Some production behavior depends on systemd/nginx files installed outside the repo; repo contains setup templates but may not prove live state.
